# 前世记忆 · 机制与验证

用户澄清后的实际流程：**一轮最终结算 → 自动更新项目根 `Memory.md` → 下一轮 AI 规划读取文件正文作为前世背景**。本文件只保存机制说明；每位玩家的实际 `Memory.md` 是运行档案，已从版本控制中移出。`user://meta.json` 保留结构化事实供恢复，`user://save.json` 保存本世安排。

## 前世记忆：当前机制

- 第一性原理：让“重新来过”改变人与人的关系，而不只是获得数值。角色偶尔记起玩家曾做过的一件事，玩家可承认、以今世行动回应，或将它视作旧梦。
- 重新开一卷才是新的一世。翻回昨日仍是同一世，被撤销的行动不会进入最终前世档案。
- 只从有效选择记录事实：给药不等于救活；拒绝不等于害死。AI 自由文案、日志和旧存档的 runs/deaths 不能反推前世经历。
- 一世结算才归档。本世 ID 去重，保留最近八世的详细事实，每世最多十二条；归档 ID 同时保护道心、局数和每日成绩，重复回调或旧存档不能重复领取整轮收益。
- 每局将有往事的角色随机排序，逐个以 45% 概率尝试安排觉醒，达到两位即停止；每人每世最多一次，日期在第 2–8 日。抽取使用独立随机源，安排随存档保存，不影响尸潮和掉落随机数。
- 觉醒离线可玩，不等模型、不依赖动态世情开关。已有固定任务与夜战优先；每日一局也更新轮回结局摘要，但不触发觉醒、不归档其 NPC 往事、不将旧世档案用于每日局 AI。
- 片段本身不自动发奖或扣物资。玩家回应才产生明确的人情/心神变化；赠米选项有真实成本，始终留有无需物资的出口。
- AI 编剧接收从 `Memory.md` 实际读回的旧世背景，即使当前尚无人觉醒也可预先布局。角色只能依据自己的已觉醒片段知情，不能把编剧知识当作 NPC 记忆。觉醒会废弃未展示的未来候选，已许下的约定不变。

## Memory.md 写入与读取

- 最终合卷、重新轮回时写入；仅进入死亡或任一结局画面不写，玩家仍可选择回溯或结局允许的后续。只有坚守结局能继续原宅无尽；提前撤离没有守满20日奖励，破阵仍须守过20夜才结案。重复结算不重复入档、不重复发道心。
- 默认位置为开发项目根 `Memory.md`；有八世结构化记录，文件优先呈现最近一世及篇幅允许的较早轮回，包括身份、模式、结局、死因、守波、关键选择、确证往事与结算人情。
- 人情交易新增独立「旧世交易结算」：最终信任/人情/失约、未清借债、待收回礼不依赖有限历史片段。旧债与回礼仅作为前世背景，不会变成本世的债务或奖励；每日局保留真实摘要但仍不产生 NPC 继承事实，验证见 [17](17-relationship-trade.md)。
- 危机新增「旧世风声与危机结算」，最多六场公共结案及当前未结案的公开预兆；仍未知的真假保持未知，不归档私有提案。旧世危机不直接成为新世处罚，验证见 [18](18-crisis-clocks.md)。
- NPC新增「旧世邻人自主行动」，归档最终周转物资、政策、有限行动历史及待执行/已执行状态。凭情改托明确原行动取消；待送不写成已兑现，旧库存和旧待送不带入新世。只保留每人最新有意义的自主因果供未来真实觉醒，日常意图与普通筹措不挤掉关键人物往事；规则决定只读本人已觉醒片段，见[19](19-npc-autonomy.md)。
- 主线新增「旧世主线与结局」：实际交回的义庄/青云观证据、断运/封阵完成时刻、锁定路线、未完成工作和坚守/撤离/破阵实际结局；不归档工作私有data。调查20分钟后仍要完成60分钟真实返程才算证据；封阵90分钟现场完工才记为生效。筹备与材料投入不等于已离城或已破阵，旧残卷/旧路线/旧施工不能代替新世证据，也不自动给未觉醒NPC知识，见[20](20-mainline-endings.md)。
- M4新增「旧世身份专属解法」：记录今世实际完成的方法、学习能力与有限历史；施工未完成只保留动作和期限，不宣称已学会。归档还检查本身份、真实时钟、本世交证、有效旧世资格和每日限制，避免旧/异常状态把失活能力写成成果。主线可选保留真实撤离方式（常规/轻装/旧路早行）与封阵方式（常规/纸阵），以便回指代价；缺这些字段的旧档仍可读取，公开主线AI字段维持原9项。
- 先保存跨轮回 JSON，再经临时文件原子替换 Markdown。缺失或落后时从最新 meta 恢复，同世手工编辑及较新档案不会被旧卷覆盖；失败保留旧档并提示。
- `StoryDirector` 读取真实文件，快照的 `archive.markdown` 即读回正文，`archive.sha256` 绑定文件内容；摘要不是由 JSON 临时改名冒充文件输入。
- 文件变化会改变请求 ID 和去抖签名；在途响应发现档案已变则丢弃。相同请求继续缓存去重，不重复消耗套餐。
- Markdown 最多 8000 个 UTF-16 单元，桥接请求最多 64 KiB，完整提示词超过 24000 个 UTF-16 单元会在调用 CLI 前拒绝。若最新一世同时含交易、危机、NPC、主线与身份专法，先压缩重复长叙述和近史，保留各系统结算区块，避免新增系统把最新一世整段丢掉；原始meta不因此裁切。较老轮回细节可能按篇幅省略。
- 隔离存档的旧测试默认禁止根文件 IO；新流程测试显式指定独立 save/meta/Memory 三路径。`no_save` 禁止写入和恢复档案。

## 身份专法使用的真实旧世来源（M4首批）

身份解锁从已封存结构化记录读取，不解析Markdown自由文案、动态事件字符串或旧计数。每类只取最新合法来源，要求ID确已封存、世次合法、非每日局、身份与结构化事实有效。

| 真实旧世经历 | 可解锁本世备选 | 不视为完成的情况 |
|---|---|---|
| 交回青云观证据后实际完成七灯封阵，之后死亡合卷也可积累经验 | 书生纸阵筹备 | 只投入法具、现场工作尚未完成、超过最终窗口 |
| 实际达成「离城余生」 | 趟子手旧路早行 | 仅选撤离或备好行装；第17日记录还须确认为早行方式 |
| 实际将药交给阿宁的正向 `medicine` 事实 | 药徒药墨符方 | 承诺、留药、迟交、自由文案；交药也不推断病人治愈 |
| 本世义庄证物实际调查并完成返程交回 | 更夫本世尸潮数量/特性情报 | 贴身携带尚未交回、旧残卷、已解锁地点 |

开新世时将来源固定在 `run.identity.inherited`；之后查询不重新读取meta，旧卷或旧快照不会吸收后来才封存的经验。存档v18为旧卷补空来源，不凭旧 `runs/deaths/clues` 推造经历。选择、施工和已学能力随本世快照回溯，撤销的行动不归档；重复结算仍由原本的本世ID去重。旧债、旧库存、旧NPC关系和旧证物不会跟着经验发放。

玩家已经确证的四类经验保留在 `past_lives.identity_legacy`，每类仅一个最新合法来源，最多4条 `tag/source_life/source_id`。它和最近8世详细叙述分开保存，资格不会随旧叙述裁切失去。成功归档在裁切前合并严格有效的非每日来源；源ID仍须确已封存、世次不得超过总数，来源仍有详细记录时再次核对实际非每日事实。每日合卷不贡献自己的经验，但会保留旧卷中尚可核实的普通轮回经验，避免连续每日局把它裁掉。重复归档不改变索引。

没有索引的旧meta只能从仍有记录的最多8世建立资格；已经丢失的更远经历不会从总局数、封存ID或Markdown自由文案补造。索引不给NPC额外知情，不恢复旧资产或今世证物；新的来源只对之后新开的一世生效，既有本局来源仍固定。

每日局保留本身份基础方法，禁用前世替代法；开局标旗、查询、行动、制作、公开AI上下文和归档都会检查，不能靠按钮置灰保证公平。四身份八法、3配方和3替代筹备见[21](21-identity-paths.md)。本批只交付身份专法首批，改变局势的开局条件和更多跨轮回事件仍未开发。

## 后续方向

阿宁的给药/拒绝/留药/失约/药账记忆，以及老周、过路客的实际物资往来已交付；M4首批让封存经历进一步提供身份解法。以后再扩展不同角色记忆不一致、隔世承诺、记忆互证、轮回调查及可变开局条件；不能靠AI临时捏造前世真相。

## 开发约定

先用第一性原理定义玩法与验收，再对抗审查重复结算、回溯、旧档、每日局、断网和人物全知等反例。按功能提交，使用 `type(scope): 中文摘要` 与“改动 / 验证 / 未验收范围”正文，保留并行任务改动。提交和推送遵循当轮授权；本批主线已获授权每批提交后立即正常推送并核对远端SHA，不force、不部署。

运行时导演入口见 [13-dynamic-director.md](13-dynamic-director.md)，完整内容路线图见 [10-roadmap.md](10-roadmap.md)。
