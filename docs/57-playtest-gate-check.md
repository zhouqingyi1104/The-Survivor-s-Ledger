承接 [37 优化路线图](37-optimization-roadmap.md)。上一批（[56](56-test-red-and-cleanup.md)）把基线测试修绿并清了测试残留。这次没有新功能可做——A/B 两条线都卡在 A4 真人试玩上——所以本批不写代码，先把三件"下次又要重新推一遍"的事核准：**包是不是最新的、退出告警到底是谁的、寻常档能不能靠调数值变难**。

|---|---|---|

## 1. 包与代码是否一致

包在 `build/windows-release/`，`构建来源.txt` 与 `package-provenance.json` 都记着来源提交 `2bca5ee`；HEAD 是 `bd54064`。

```
$ git diff --stat 2bca5ee..HEAD
 docs/55-test-storage-isolation.md | 105 ++++
 docs/56-test-red-and-cleanup.md   | 108 ++++
 scripts/autoload/game.gd          |  34 ++++
 tests/storage_isolation.gd        |  47 ++++
 tests/storage_isolation.tscn      |   6 ++
 tests/ui_smoke.gd                 |  11 +-
```

三处差异都在测试面：

- `game.gd` 新增的 34 行是 `_isolate_test_storage()`，第一句就是 `if OS.has_feature("template"): return` —— **导出件里直接返回**，不碰任何路径；
- 其余是新增/修改的测试文件，发布预设本来就把 `tests/` 排除在包外。

所以"包里的游戏"和"HEAD 的游戏"是同一套规则、同一组数值。**这解释了为什么本批不需要重打包**——不是省事，是确实没有玩法差异。（[50](50-windows-release.md) 之后已经重打过一次，见 [51](51-offline-events.md)。）

启动实测：

| 运行方式 | 结果 |
|---|---|
| `build/windows-release/劫余录.exe --headless --quit-after 90` | 退出码 0，仅第 2 节那两行音频告警 |
| 编辑器窗口模式 `--rendering-method gl_compatibility --quit-after 120` | 无输出、无告警 |
| 编辑器窗口模式默认（Vulkan / Forward+） | 无输出、无告警 |

顺带把 fast 档跑了一遍：`PASS=1 PASS_WITH_WARNINGS=4 FAIL=0 NOT_RUN=0`（4 个"带警告"就是第 2 节那两行的历史噪声，不是失败）。

## 2. 退出告警：四组最小探针

`docs/31`、`docs/43`、`docs/50` 都记着"退出仍有 RID/ObjectDB/资源清理警告"，一直没人查到底。这次用四个十行探针分清楚了（探针在 `build/probe_*.gd`，未入库）：

| 探针 | 做什么 | 退出时 |
|---|---|---|
| A 只载入 | `load(".../lotus_pond.ogg")` 后退出 | **干净** |
| B 播完再退出 | 加播放器、`play()`、0.3 秒后 `quit()` | 6 ObjectDB + 2 资源 |
| C 先停再退 | `stop()` + `stream = null` + `queue_free()` + 等 2 帧再 `quit()` | **干净** |
| D 靠 `tree_exiting` 停 | 播放器 `tree_exiting` 里 `stop()` + 松流 | 仍报 6 + 2 |

四组一起说明三件事：

1. **和载入无关**（A 干净），必须是"正在播的时候退出"（B 报）。
2. **只要停干净就能不报**（C 干净），但**必须让音频服务器跑过一帧**——`tree_exiting` 里停（D）来不及，因为退出时不再有混音过程。
3. **窗口模式本来就干净**（1 节的表）。只有 `--headless` 的 Dummy 音频驱动会报，也就是说：**报警只出现在无头测试日志里，玩家一次都看不到。**

所以这条"工程债"的正确处置是**不改**，不是修：要消掉它得把所有退出路径改成"先停音频、等一帧、再退"，包括 `--quit-after` 和测试里的 `get_tree().quit()`（这两条改不了），换来的只是测试日志干净。风险（退不出去、测试挂住）明显大于收益。**建议 [37](37-optimization-roadmap.md) 的工程债第 3 条按"引擎侧，已查明"关闭。**

## 3. 寻常档：不能只调尸潮

[44](44-balance-retest.md) 第 58–60 行记着一次已做过的实验：寻常档尸潮倍率提到 **2.7**，同一批种子下——

| 打法 | 原参数 | 2.7 倍 |
|---|---|---|
| 两趟 + 差事（高手臂） | 24/24 | 15/24 |
| 旧一趟无差事（新手臂） | 13/24 | **0/24** |

也就是说，**尸潮这条杠杆一动，先死的是不会玩的人**：高手臂刚好落进建议区间，新手臂直接归零，于是那次被否决、参数保留。

这解释了一个容易被误读的现象：机器人 24/24 不等于"寻常太简单"。机器人的 24/24 来自"一天跑两趟 + 排满差事"，而真人第一局不会这么打；[52](52-balance-after-offline-events.md) 里同一档的旧打法对照臂在两个独立种子组分别跑出 **7/24** 与 **24/24**，**方差本身就大到不能拿单组胜率当结论**。

结论：**寻常档的问题是"两趟/差事的收益压过了尸潮"，不是"尸潮太弱"**，改它就会同时改到 B5（白天节奏）和新手容错，两件都得等真人数据。冻结期不动数值。

## 4. 为什么本批没改代码

按 37 的"只看玩家感知得到的变化"这条标准，把三个候选都过了一遍：

| 候选 | 否决理由 |
|---|---|
| 拆 `dialogs.gd`（2280 行，60 个面板） | 玩家零感知，而且**正在这个包要发给第一批人的时候**动 60 个弹窗，是拿试玩机会换代码整洁。等试玩回来、知道哪些面板真被打开过再拆 |
| B1 后续批：主线/危机/身份的"条款密度" | 实际读下来，这几页的正文是**状态**（第几轮、还剩几分钟、要查什么），不是 39 里那种规则条款；真正该收的条款在夜战面板，B1 已经收完。没有证据就先不删玩家的信息 |
| 调难度（寻常/永夜） | 见 3：已被 44 的反例否证；且违反"不以高手目标直接压低新手容错" |

这不是"没活干"，是**这个阶段所有能改的东西都缺一个前提：有人真的玩过**。

## 5. 今天能做的三件事

### 5.1 发什么

`build/windows-release/` 整个文件夹（`劫余录.exe` 109 MB + `劫余录.pck` 231 MB + `读我.txt` + `字体许可.txt` + `构建来源.txt`），压成 zip 发。**exe 与 pck 必须同目录**，这一点 `读我.txt` 第一段就写了。

### 5.2 说什么（可直接复制）

> 一个我自己做的生存游戏，20 天守一座院子，一局大概一小时。不用看攻略，死了没关系——死了才是重点。
> 三件事想请你留意：① 你知道自己是怎么死的吗？② 玩到第 10 天左右，有没有"想做但做不了"的事，是什么拦着你？③ 二十天是长了还是短了，从第几天开始觉得重复？
> 玩完（或者玩不下去想关掉）的时候，在标题或生死簿残页上点「导出试玩报告」，把三问填一下（空着也能导），再把导出的整个文件夹发我。画面有问题另外截个图。

### 5.3 收什么

每个玩家一份 `reports/<时间戳>/` 文件夹，里面应当有 `report.md`（含种子、难度、死因账本、最后 40 条日志）+ 本局存档快照。**没收到报告 = 这一局等于没玩**，因为种子和死因没法从"我觉得有点难"里还原。

回收后按 37 的度量表填：首次死亡日、能否说出死因、第 10 日卡在哪、一局实际多长、在哪里放弃。

- 第 2 节的探针只覆盖"一首 ogg 配乐"，没有覆盖多路同时播放、以及无头下播放中被打断的其他组合。
