# 难度预设平衡验收（v0.8）

> **状态：已实现，数据是 v0.8 当时的。** 之后又加了挑战自选、同院的人、加工配方等，会改变整局强度；最新的多局实测见 `docs/09`。要拿现状的数，按第 1 节重跑。

> 数据来自 `tests/sim_test.gd` 的「难度 × 6 局」对照段，机器人策略固定（稳守方针 + 固定购物清单），
> 只改难度 id，因此表里的差异**全部来自难度参数本身**，不含策略差异。

## 1. 怎么跑的

```
rea 命令：无（本地引擎）
godot --headless --path . --script res://tests/sim_test.gd
```

- 每档 6 局，身份轮换（scholar / escort / herbalist / watchman），seed 4000+k
- 机器人策略：备劫按固定清单采购 → 灾后每天做饭 / 打理菜畦 / 打水 / 小憩 / 上香，夜里稳守
- 统计三项：**劫满率**（活过第 20 日）、平均存活日数、终局气血

## 2. 结果

| 难度 | 劫满 | 平均存活 | 终局气血 | 结论 |
|---|---|---|---|---|
| 暖冬 | **6/6** | 20.0 日 | 92 | 对机器人无压力 |
| 寻常年景 | 4/6 | 18.7 日 | 56 | 默认档，六成七 |
| 荒年 | 3/6 | 18.3 日 | 38 | 对半开 |
| 永夜 | 2/6 | 18.0 日 | 20 | 三成三 |

**读法：**
- 曲线单调，四档没有倒挂——说明六个乘数都在起作用，没有互相抵消。
- **平均存活日数几乎不动（20.0 → 18.0）**，因为死都死在最后几波尸潮（第 17、20 夜），
  难度影响的是"能不能撑到"，不是"撑多久"。所以这个指标参考价值低，看劫满率就够。
- 终局气血掉得很快（92 → 20），说明难度主要透过"气血上限"和"尸潮规模"两项咬人，
  而不是饿死冻死——后两项（食量、水量、寒冷）在这套机器人策略下没成为主因，
  因为它每天都做饭、打水，20:00 也自动取暖。

## 3. 样本量与可信度

**6 局一档，样本很小。** 2/6 和 3/6 之间只差一局，噪声可能有一档之多。
这张表只能说明"四档的排序和量级对"，不能说明"永夜正好是三成三"。

而且这是**机器人**：它的购物清单是写死的优解，夜里永远稳守。
真人会更差（乱买东西、该修不修、该跑不跑），所以真人的劫满率应当**低于**表中数值。

## 4. 参数是怎么定的（可复算）

`data/difficulty.json`，四档共用同一组乘数名：

| 参数 | 作用点 | 寻常年景 |
|---|---|---|
| `silver_mul` | `State.new_run` 的开局银两 | 1.0 |
| `hp_mul` | `State.new_run` 的 `hp_max` | 1.0 |
| `food_mul` | `post.gd` `_tick` 的每小时饱腹消耗 | 1.0 |
| `water_mul` | `post.gd` `_tick` 的每小时水分消耗 | 1.0 |
| `cold_add` | `post.gd` `cold_of()` = 天气 cold + 此项 | 0 |
| `wave_mul` | `defense.gd` `wave_for_day()` 的尸潮 count | 1.0 |

**极值验算：**
- 银两：书生基准 22000 文。永夜 0.6 → 13200 文，还够买清单里的大半（清单总价约 16000），
  所以永夜不是"买不起"，是"买不全"。暖冬 1.25 → 27500 文，能买全还有剩。
- 气血：书生基准 100。永夜 0.9 → 90，即一开局就少 10 点，等于白挨两口咬。
- 食量：`RATE.food` = 2.0/小时。永夜 1.35 → 2.7/小时，一天（醒着 16 小时）掉 43.2，
  80 点饱腹撑不到两天，必须每天做饭。暖冬 0.85 → 1.7/小时，一天掉 27.2。
- 寒冷：冬至天气 cold = 30。永夜 +14 → 44，夜里每小时掉 4.4 体温，不取暖一夜掉 70+；
  暖冬 −8 → 22，每小时掉 2.2。**暖冬不会低于 0**（最低 30−8=22），所以照样要取暖，
  不会出现"永远不冷"。
- 尸潮：第 11 夜基准 24 只。永夜 1.35 → 32.4 → `maxi(1, round())` = 32；
  暖冬 0.85 → 20.4 → 20。第 20 夜血月基准 58 × 1.35 = 78，再叠血月自己的 1.2 = 93.6 → 94 只，
  这是全表最陡的一夜。

## 5. 第二组：懒策略 × 难度（补验食量 / 水量 / 寒冷）

上一组用的是勤奋策略（每天打水、做饭、修门、种菜），所以食量/水量/寒冷三项根本没成为主因。
换成"只做饭睡觉、不打水不修门不种菜"的懒策略再跑一轮，专门逼出这三项：

| 难度 | 劫满 | 平均存活 | 终局气血 | 饿/渴死 |
|---|---|---|---|---|
| 暖冬 | 0/4 | **10.3 日** | 0 | 4/4 |
| 寻常年景 | 0/4 | **8.8 日** | 0 | 4/4 |
| 荒年 | 0/4 | **7.3 日** | 0 | 4/4 |
| 永夜 | 0/4 | **6.3 日** | 0 | 4/4 |

**读数：**
- **四档全灭，且没有一局是冻死的**——4/4 全是饿/渴死。说明在"不打水"的前提下，
  水量先于体温见底；`cold_add` 要等水和粮都断供之后才咬得动人，懒策略走不到那一步。
- **平均存活日数这次真的动了**：10.3 → 8.8 → 7.3 → 6.3，四档差出 4 天。
  对比勤奋策略那组的 20.0 → 18.0（只差 2 天），说明**食量/水量乘数确实在起作用，
  只是被"每天打水做饭"这个动作掩盖了**。上一节"这两项没成为主因"的判断，现在有了反证。
- 永夜比暖冬少活 4 天，量级合理：食量 1.35 vs 0.85，饱腹见底速度差 59%，
  叠加水量 1.25 vs 0.85，断供时间差四天对得上。

**两组对照的结论：** 六个乘数没有一个是摆设。
勤奋策略下咬人的是气血上限 + 尸潮规模；懒策略下咬人的是食量 + 水量。
`cold_add` 是唯一一项两组都没单独验到的——它需要"粮水不断但没柴"的局面，
现有两个策略都做不到（一个天天打水，一个不断粮但也没柴可烧）。

## 6. 第三组：`cold_add` 单点注入（补验最后一项）

前两组都验不到 `cold_add`：勤奋策略粮水不断、懒策略粮先断，都走不到"没柴冻着"那一步。
所以在 `test_difficulty` 里直接摆局面：**冬至冷夜、不生火、体温从 100 起跑，测前 3 小时**。

| 难度 | 冷夜掉温 | 每小时 | 理论值 `cold/10` |
|---|---|---|---|
| 暖冬 | 6.6 | 2.20 | 22/10 = 2.2 |
| 寻常年景 | 9.0 | 3.00 | 30/10 = 3.0 |
| 荒年 | 10.8 | 3.60 | 36/10 = 3.6 |
| 永夜 | 13.2 | 4.40 | 44/10 = 4.4 |

**实测和理论值逐档吻合，`cold_add` 确认生效。** 至此六个乘数全部有据。

**踩到的坑（记下来，下次别再犯）：** 第一版让体温从 **20** 起跑、测 6 小时，结果荒年和永夜
都"掉"了 20.0 —— 那不是掉速，是**体温掉到 0 就封顶了**。起始点太低 + 窗口太长，测到的是地板不是斜率。
改成 100 起跑、3 小时窗口才对得上。同理，掉血也不能在这种注入里测——会掺进
"体温 < 30 / < 15"两档阈值伤害，不是单纯的 `cold_add`。
