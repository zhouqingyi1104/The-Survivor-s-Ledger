# 文案规范与第一轮审查（2026-10-29）

玩家看到的每一句话都按这篇写。第一轮审查的结论、已改内容和待改清单也记在这里。

## 0. 结论

游戏里有 4279 条中文字符串，约 4.9 万字。通读下来，有两种声音：

- **故事里的声音**：玩法说明、事件、物品与配方描述、守夜方针、死亡页。短，具体，白话里带一点古风，直接对「你」说。例如「两捆柴压成一筐木炭。同样过一夜，轻 2 斤，火到后半夜也不会弱。」
- **开发者的声音**：集中在后来加的几个系统，包括主线、身份专法、可变开局、轮回调查、危机、邻人自主行动、纸鹤交易，以及针对布防的说明。读起来像合同条款，有三个特点：
  - 规则一再重复，「完工才生效」「中断不退」「投入不退」这类话共出现 37 处。
  - 大量为了防止误读写的否定句，比如「不代表」「没有凭空增加物资」「旧债没有被带来」。
  - 把实现方式也写了出来，比如「来访不靠随机抽取」「保留最近八世」「独立契约货盘」。

本批先改掉了**明确的开发内容外泄**，共 55 处。术语统一、数字格式和合同腔改写需要按本篇规范分批做，清单见第 3、4 节。

## 2. 规范

### 2.1 声音

1. **对玩家说「你」。** 不说「玩家」「NPC」「AI」「系统」「功能」「机制」。
2. **用故事里的叫法。** 主线叫「尸劫来历」或「调查」；任务目标叫「要查的」；剧情调查叫「查访」；时间窗口叫「期限」。不说「主线」「任务」「剧情」「窗口」「阶段」「干预」「入账」「结案」「专点」。
3. **只说会发生什么、要花什么。** 不解释程序怎么做的：随不随机、存几世、数据放哪里、断网怎样。
4. **不写防误读的否定句。** 「不代表……」「没有凭空……」「不等于……」这类只在一种情况下写：玩家很可能误会，而且误会会让他吃亏。写的时候也只说一次，说成正面的话。
5. **通用规则只讲一次。** 「开工先付料，做完才算数，中途被打断料不退」写进玩法说明；按钮旁边最多一句短提示，不在每条消息里重复。
6. **一句只说一件事。** 面板正文一般不超过 40 字，超过就拆开，或者挪进悬浮提示。

### 2.2 术语表

| 说的是 | 用 | 不用 |
|---|---|---|
| 以前的某一世 | 前世 | 旧世 |
| 正在过的这一世 | 这一世；四字短语里用「今世」 | 本世 |
| 活过第 20 日 | 劫满 | |
| 生命值 | 气血 | 生命 |
| 精神值 | 心神 | 心情、心态 |
| 体力值 | 精力 | 体力 |
| 一夜来袭的整批 | 尸潮 | |
| 成群的尸 / 单个 | 尸群 / 僵尸 | |
| 隔壁的人物 | 邻人 | 邻居、NPC |
| 取证的地方 | 义庄、青云观（直接说地名） | 专点 |
| 截止时间 | 期限 | 窗口 |
| 外出暴露值 | 阳气外泄（篇幅紧时写「外泄」） | 暴露 |
| 存档 | 系统提示里写「存档」；标题和结局页沿用「此录 / 这一卷」 | |

### 2.3 数字、时刻、标点

- **汉字和阿拉伯数字之间空一格**：第 3 日、60 分钟、精力 6、信任 +1。
- **时刻**：第 3 日 08:00；跨度写「第 18 日 08:00 至第 19 日 18:00」。不写「21晨」，写「第 21 日天亮」。
- **物品数量**：米 ×4、清水 ×2，和背包、随身物的写法一致。
- **引号一律用「」**，引号里再引用用『』。不用 “” ‘’ 和英文 '。
- **短项之间**用「 · 」，前后各空一格；**句子之间**用中文标点。
- 省略号用「……」，破折号用「——」。

## 5. 遗留问题

- **`Memory.md` 会被玩家看到**：这个文件是写给 AI 的背景，里面有「AI 编剧可据此铺垫」「NPC」「玩家」这类话。便携包会把它写进游戏文件夹，就在 exe 旁边；而打包版本来就不连 AI。建议打包版不再写这个文件，或者改写到存档目录。这牵涉档案的去向，要先确认。
- **劫余录窗口最后一个入口被裁掉**：`past_lives_ui` 报「风声与危机 · 查验与筹备」按钮被裁掉。改动前的提交上同样如此，不是本批造成的。入口太多是路线图 B2 要解决的问题。
- **开发版设置里的动态世情说明**：仍是条款式的写法，但只在开发机上出现，打包版显示的是「本包离线」。
