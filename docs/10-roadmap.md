## 目标与现状

从「撑过二十天」扩展为「活下来，并决定这座城的命运」。已有采购（含载具、同院的人）、经营（含家具摆放、工作台加工、发电机暖气）、夜战、轮回、难度、挑战自选、劫满后无尽、守到死与每日一局记分；叙事上有邻居求药支线、运行时世情导演、前世记忆，以及首条道士—义庄—青云观主线。主线取证和施工会实际改变尸潮，通向坚守、撤离、破阵三种结局。目前普通探索仍较相似、经营深度浅（没有保质期、只有固定菜谱）；主线整局节奏和长期平衡未验收。对照原版的逐项缺口见 [07-survival-log-features.md](07-survival-log-features.md) 第 11 节。

## 上一批：M5 试玩反馈（把"有点难"变成能复现的证据）

新增 `scripts/core/playtest_report.gd`（纯逻辑、可无界面测）：Markdown 一段五节——这一局（身份/难度/模式/世次/种子/开局/结局或判词/战果）、死因构成（复用扣血账本与"当时的余地"）、最后 40 条记录、跨轮回底稿、本机设置，末尾留三个待玩家填的问题。刻意只写事实：没账本就写没账本，不拿属性猜死因；日志只留末尾 40 条；不带本机路径与用户名。

## 上一批：M5 Windows 打包（能双击就玩，不再依赖仓库里的引擎）

之前能玩的唯一方式是 `启动游戏.bat` 指向 `tools/godot/` 里那台 255 MB 引擎——**仓库本身跑不起来**，别人拿到代码也玩不了，也谈不上试玩反馈。Godot 出独立 exe 必须有导出模板，而本机模板目录是空的；实测下载约 47 KB/s（7 分钟 20 MB），GB 级的包等不起，于是本批交付「不需要模板也能出可玩产物」的路径。

`tools/build_windows.ps1`（`-Mode auto|release|portable`）两种产物：`release` 是导出模板编出来的真独立程序（约 50–80 MB，**本批未产出**）；`portable` 是 `--export-pack` 出的 `.pck` + 同名运行时（不需要模板，约 375 MB，能双击就玩）。导出预设 `export_presets.cfg` 从 .gitignore 里放出来入库——发布件的参数属于工程；两个预设：发布用的排除 tests/tools/docs，验证用的反过来**包含 tests**，好在打包后的运行时里跑冒烟场景。

打包还揪出一个真问题：`Game.resolved_memory_path()` 固定返回 `res://Memory.md`，而打包后 `res://` 在 pck 里只读，于是每次存档都会弹「前世档案未能写入」。改为按实际能力判断（`OS.has_feature("template")` 或 `res://` 写探针任一命中就判只读），只读时档案落 `user://Memory.md`。

本地验证：新增 `export_smoke` 9 项（开发环境 9/0；同一场景在含 tests 的验证包里也 9/0——数据表进包、`user://` 存档可写、探针文件探完即删）；发布包负例确认不带测试（`Cannot open file 'res://tests/export_smoke.tscn'`）；便携包启动跑满 90 帧 0 条 script error/资源失败；在 pck 里渲染出一帧标题图（3D 远景、灯笼、中文字体全在，见 doc 28）。回归 check_scripts 70/0、ui_smoke 0、save_safety 60/0、pacing 33/0、death_report 66/0、input_settings 101/0。**正式 release exe、安装器、图标、签名、体积治理与打包后的人肉整轮试玩都 NOT RUN/未做**；本批不等于 M5 整体验收。

## 上一批：M5 节奏（把"干等"从罚站变成一次按键）

先量再改。给 `sim_test` 加了一路诊断（`PACING=1` 打开，默认零开销、零输出），同一机器人跑 19 局：一天真的做决定 **3.5–4.9 次**，等工序 68–152 分钟游戏时间，睡 590–615 分钟，**干等 576–651 分钟**——醒着的约 850 分钟里 73% 在干等。换算成真实时间（1x = 4 游戏分钟/秒）一天 6 分钟、一局二十天约 2 小时，其中大半是在看时间流。结构原因：上午 8:00 到傍晚 18:00 十个小时里一个强制决策点都没有，而手上的活都只要一两秒就做完。

改动只做一件事：**「等一刻」**（HUD 按钮 + 快捷键 Q）把时间直接推到下一个既有检查点（8:00/18:00/20:00/21:00/22:00/23:40/天亮，开夜后含每轮夜战结算）。跳过的只是没有事发生的分钟，`Post.advance` 本来就在检查点前刹车；手头有活、正在睡、有事件待办时 `minutes_to_next_stop` 返回 0，按键只提示「手头有事，等不了」。HUD 同时显示「空档 → 18:00」，玩家随时知道下一次停下是几点。诊断还给出关键数字：**空档每天只有 0.9–1.1 段**（整段连续的），所以一次按键就能吃掉那 600 分钟，而不是碎片化地按二十次。

顺带把流速数值（`SPEEDS` / `BUSY_RATE` / `SLEEP_RATE`）从界面搬进 core 并加了 `Post.rate()`，节奏数值有了单一来源、可无界面断言。输入动作从 17 条增到 18 条（`wait` = Q），设置界面的改键表同步；因为 Q 被占用，`input_settings` 与 `settings_ui` 里拿 Q 当改绑靶子的用例改成 Z。

本地验证：新增 `pacing` 33 项（三档流速与越界夹紧、睡眠/做事快档、一天真实秒数、六个时刻的下一个节点、四种情况拒绝跳、跳完真的停在 8:00 与 18:00、夜战轮次也算节点）、`ui_smoke` 0（新增按「等一刻」断言时间推到检查点）、`input_settings` 101/0、`settings_ui` 54/0、`mainline_ui` 354、`check_scripts` 70、`sim_test` 16/16 不变量 0 全绿。HUD 截图目视一轮修掉与心腹条相撞（doc 27）。事件密度、白天内容量、自动快进与真人试玩 **NOT RUN/未做**；本批只解决"等"，不等于 M5 整体验收。

## 上一批：M5 死因与复盘（让玩家看得懂自己怎么死的）

改前死因是在 `Post._death_cause` 里**事后按属性猜**：先看渴、再看饿、再看瘟、再看冻，全对不上就写「力竭而亡」。于是夜里被尸群扑死的人只要饱腹刚好为 0 就被判成「饿死」；翻废墟被咬死、破院被扑死、强截运尸失血全都只得到一句不带日子、不带原因的「力竭而亡」；死了以后也没有任何回到下一步的线索。

新增 `scripts/core/death_report.gd` 与 `State.hurt`：**扣血那一刻记账**（11 处扣血点全部插桩，来源分 受饿/渴/尸瘟/酷寒/受冻/院破被扑/夜战失血/出门迎战/溃兵夜袭/受伤/意外），判词由账本主项生成并带时刻；**平手取最后落下的那一击**，保证「判词说什么」与「最后一击是什么」不打架。属性猜测退为老存档兜底（且补上了日子，不再是「力竭而亡」）。生死簿残页新增复盘：死因构成（本世共失血 N：各项）、最后一击（扣前→扣后）、死前两条真实日志、以及最多两句**只引用真实库存/设施/破损**的提醒（有柴没烧、仓里有米没做饭、院门砸穿没补、没修地窖……条件不成立就不出这句）。存档 v21 补空账本，旧卷不追造历史。

## 上一批：M5存档安全（不再一断电就整局消失）
