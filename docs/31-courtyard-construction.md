# 宅院建设与周边街区

2026-10-26。用户明确将宅院建设提前，首批先解决宅院四周空白、缺景的问题。本页是专项路线与实际交付记录；未通过的阶段不标成完成。

## 目标

让宅院从“放在雪地上的孤立院子”变成“临川城街坊中的一个家”。先补环境骨架，再做家具布置、院内改造、扩建与楼层；不把补景扩大成重写城市模拟。

本批开始前：宅院有固定正屋、东西厢、门墙与可添置家具；门前有一段街，对街是简化盒体剪影，侧面、背面和中远景尚未连成街区。镜头可以全周旋转、缩放到 7—26、俯仰到 -80°—-20°，因此不能只补默认镜头看到的一面。

## C0 首批范围

### 景观层级

- 核心宅院：现有家具、库存、门窗墙、守具和作物，不改数值与坐标。
- 近邻：左右相邻屋舍、后巷和对街院落；墙体转折、门楼、附棚有差异，不整齐复制同一种房子。
- 中景：错落屋脊和巷道延续，树木与少量街道构件连接地面，避免建筑孤零零立在白底上。
- 远景：低成本城市轮廓、城墙和山形，收住视野，不新增可进入剧情地点。
- 南街：保留现有守具摆放、尸潮进场与门前战斗视线；不把敌人藏到房子或树后。

### 技术边界

1. 周边生成与核心宅院分离，显式分近/中/远层；不会在每次库存刷新时重建整个街区。
2. 背景不带可交互标记和静态碰撞，不扩大现有玩家导航；不制造“看得见就能走进去”的假承诺。
3. 使用固定布局或独立确定性装饰来源，不消耗本局规则随机序列。
4. 优先复用已有代码构件与材质，无需下载新素材；缺少本地写实贴图时沿用项目回退路径。
5. 保持现有镜头范围与低雾浓度，不靠加浓雾、压黑画面或限制转镜头遮住缺景。
6. 静态合并/批量绘制控制绘制调用；远景不使用整套高细节可交互建筑。

### 明确不做

本批不包含家具挪位、楼层、开放邻宅、NPC迁居、常驻路人AI、实时城市模拟、新生存数值或新主线。

## 验证方法

- 使用测试场景、隔离 APPDATA/LOCALAPPDATA 和 no_save；不改玩家存档、跨轮回底稿和根 Memory.md，不调用真实 ARK。
- 先采改前截图与帧时间，再在同机、同分辨率、同镜头、同光照下对照。
- 结构测试不能代替画面验收：要检查正背左右、斜向、缩放/俯仰边界、昼夜和尸潮可读性。
- 背景显示/重建不得改变库存、时间、任务、敌情和规则随机；也不能挡住拾取、描边、点击地面和关键路径。
- 性能记录真实帧时、绘制调用与节点数，区分着色器预热和稳定采样；不把截图写盘耗时算作正常帧时。
- 受影响回归包括脚本编译、整局模拟、界面冒烟、主线/邻居窗口、存档安全与输入设置。

## 后续营造的硬边界

- 目前 Home.move 已有规则函数，但家具菜单未接挪位；不能把函数存在当作玩家功能完成。
- 核心家具仍含固定模型/站位，NightFight 含固定受袭目标；开放核心挪位前必须统一位置来源。
- 搬动不能重置腌制/熏制计时、清除花盆作物或复制产物；不能以摆放装饰封住必要路径。
- 新功能描述只写实际效果：没有保质期系统时不宣传延长保质期，不把纯视觉棚子说成已提供储物保护。
- 既有地窖已影响温度，后续可进入空间不能再发一次相同收益。
