## 玩家得到什么

离线试玩包每天有一件可处理的世情，事件有不同的物资、风险与人情取舍；相邻日尽量不遇到同一件事。沿用已有事件弹窗、选择结算与局内日志，不增加入口、系统或玩家操作层级。

## 实现范围

1. 改动前 `events.json` 总数 23，实际可随机抽取只有 11（另有 7 条邻居剧情、5 条已由专门系统替代的旧事件）。本批新增 49 条静态原创事件，使随机池达到 60、总表达到 72；不能以不可抽取剧情凑数。不把新写内容宣称为真实 AI 回放或玩家证实。
2. 使用已有 `req` / `fx` / `min_day` / `max_day` / `once` 条件、实际 57 件物品及现有属性结算。新增项至少两种有差异的选择，始终有无物资要求的退路；文案明确成本和后果。奖励保持小额，不送关键主线解锁、跨轮回资格或免费高价设施。
   小额银钱选项须精确显示「文」及两/文余数，修正旧事件提示将不足一两显示为「银 0 两」的问题，不改全局货币或交易数值。
   对抗审查已复现精力为 0 仍能用负效果钳位免费换物：固定精力成本需在选择前按真实浮点余量检查，不足则禁用并给出原因；随机伤害仍是玩家明确承担的风险。覆盖差 0.1、恰好够用、原子拒绝和零精力退路。
3. 沿用每天 08:00 的日间事件检查点，优先邻居、已接受的动态导演事件，主线仍走原有独立发布；空闲时由离线池补位。不覆盖待处理事件，不连弹补偿过去的日子，不借事件绕过外出返程、夜袭或既有剧情时限。原首日禁抽与 60% 空抽会阻止达到每日密度目标，本批取消并补首日可选内容；以第 1–20 日的实际事件呈现计数，高优先级剧情也算该日一件，不能用随机函数调用次数替代玩家呈现。
4. 事件优先抽取本局未见项，耗尽后沿用可重复事件；`once`、日期/flag 条件继续生效。固定种子/随机游标决定选择，不引入真实时间或外部随机源；旧存档不要求新字段，每日一局保持可复算。不会把新事件密度等同于 B4 已重新平衡。
5. 新增内容/调度定向测试及一个真实窗口用例，登记统一入口；覆盖实际可抽数、日期范围、物品/effect 引用、可支付与不足时拒绝、每个分支效果、无物资退路、去重与 once、固定种子、08:00 剧情优先和 pending 不覆盖。对抗审查检查免费优势选项、无效条件、死分支、重复事件和秘密主线授权。
6. 从验证后的提交正常推送并核对远端 SHA、读取 CI，再刷新离线 Windows 试玩包。保留文案及美术任务改动，不动 `.env`，不调用真实导演，不为通过测试放宽检查。失败只重跑失败项，full 不在本批日常验证范围。
