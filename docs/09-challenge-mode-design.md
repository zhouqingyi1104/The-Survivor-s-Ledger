# 挑战自选设计（待确认）

> 这是**提案**，不是已实现的东西。对应原作 `ChallengeSetup`（`ChallengeAbility` / `ChallengeDebuff` / `ChallengeTarget` 三张表）。
> 确认后我再动工程。下面凡标「待确认」的，都是需要你拍板的点。

## 0. 先说定位：挑战**不能**做成第二个难度

v0.8 已经有难度预设（暖冬 / 寻常年景 / 荒年 / 永夜），六个乘数管的是**数值**：
开局银两、气血上限、食量、水量、寒冷、尸潮规模。

如果挑战模式再加几个乘数，它和难度就是同一件事的两种说法，玩家会觉得重复。

**所以挑战改的是「行为约束」，不是数值。** 一句话区分：

| | 难度 | 挑战 |
|---|---|---|
| 改什么 | 同样的玩法，数字变难 | 换一种玩法，或者少一条路 |
| 例子 | 尸潮多 35% | **整局不许点灯** |
| 失败方式 | 更容易死 | 你可能根本活不到死，因为路被自己堵了 |

## 1. 三部分设计

### 1.1 誓约（对应 Debuff）—— 核心

自愿放弃某条路，换道心倍率。**这是整个模式的主体**，因为它产生的压力是难度预设给不了的。

| id | 名字 | 约束 | 倍率 | 怎么验 |
|---|---|---|---|---|
| `no_lamp` | 不点灯 | 整局不买也不用灯油 | ×1.15 | 购买记录里没有 `lamp_oil` |
| `no_trap` | 不设笼 | 不摆捕鼠笼 | ×1.10 | 家具有没有 `rat_trap` |
| `no_door` | 不修门 | 院门一次都不修 | ×1.20 | 修门计数器为 0 |
| `bare` | 空手 | 开局丢掉所有随身物 | ×1.15 | 开局瞬间生效，无需追踪 |
| `one_trip` | 一趟 | 备劫三日只回家卸货一次 | ×1.15 | 回家计数器 ≤ 1 |

**倍率是相加的**：三个誓约 = 1 + 0.15 + 0.10 + 0.15 = 1.40。上限 1.5，防止叠满变成 3 倍。

### 1.2 凭仗（对应 Ability）—— 让新手也能试

多给一样东西，但倍率下调。作用是**降低试错门槛**，不是奖励。

| id | 名字 | 给什么 | 扣减 |
|---|---|---|---|
| `extra_oil` | 多带油 | 开局 +2 桶柴油 | −0.10 |
| `extra_wood` | 多备柴 | 开局 +6 捆柴、+2 筐炭 | −0.10 |
| `free_room` | 现成屋 | 开局自带一间设施（自选） | −0.15 |

### 1.3 了愿（对应 Target）—— 一局的目标

达成才拿满额。**全部只用已有字段，不需要新埋点**：

| id | 名字 | 条件 | 奖励道心 |
|---|---|---|---|
| `slay_200` | 杀满 | 斩尸 ≥ 200 | +20 |
| `hold_all` | 全守 | 七次尸潮全部守住 | +25 |
| `no_death_day` | 活到终局 | 活到第 20 日（不靠翻生死簿） | +15 |

## 2. 新增状态与改动点

**只加一个字段**：`run.tally`，一个小字典：

```gdscript
"tally": {"bought": {}, "repair_door": 0, "home_trips": 0, "vows": [], "boons": [], "goals": []}
```

| 改动点 | 改什么 | 成本 |
|---|---|---|
| `data/challenge.json` | 新表，三张（vows / boons / goals） | 纯数据 |
| `state.gd` `new_run` | 收 `challenge` 参数，写进 `run.tally`；凭仗的开局物资直接发 | 小 |
| `pre.gd` `buy()` | `tally.bought[id] += n` | 1 行 |
| `pre.gd` `travel("home")` | `tally.home_trips += 1` | 1 行 |
| `post.gd` `act_repair("door")` | `tally.repair_door += 1` | 1 行 |
| `ledger.gd` `daoxin_gain` | 按誓约倍率乘、按了愿加成加 | 小 |
| 新界面 `challenge_screen.gd` | 和难度界面同构：勾选 + 底部确认 | 中 |

**不需要**改：尸潮、夜战、种植、烹饪——誓约和了愿都不碰这些系统的内部逻辑。

## 3. 数值验算（必须看，可能给多了）

基准：一局寻常年景、稳守、活满 20 日的道心 ≈ **49**
（20 日 = 20 + 守住 7 次 = 14 + 残卷约 3 篇 = 15）

| 场景 | 计算 | 道心 |
|---|---|---|
| 寻常年景，不了愿 | 49 | 49 |
| 三誓约（1.40），不了愿 | 49 × 1.40 | 69 |
| 三誓约 + 了愿全达 | 49 × 1.40 + 60 | **129** |
| 三誓约 + 一个凭仗（−0.10） | 49 × 1.30 | 64 |

**问题：129 是基准的 2.6 倍。** 天赋一个 8–20 点，等于一局挑战能买 6–8 个天赋，解锁太快。

两个可选方向，**待确认**：

- **A（保守）**：誓约倍率上限降到 1.30，了愿奖励减半（+10/+12/+8）。三誓约全达 ≈ 49×1.30+30 = 94，约 1.9 倍。
- **B（激进）**：保持 129，但把挑战限定为**劫满之后才解锁**，当成长线内容，不作为前期主要收益来源。

我倾向 **A + 挑战和难度可以叠加**（荒年 + 三誓约 = 真的很难，也真的给得多）。

## 4. 建议交付顺序

1. **第一步只做了愿**（3 个目标 + 结算加成）。零新埋点、纯读已有字段，改 `ledger.gd` 加 20 行就够。能先验证"目标能不能驱动玩法"。
2. **第二步做凭仗**。纯发东西，同样零埋点。
3. **第三步才做誓约**。要加 `tally` 和四处埋点，还要考虑"中途违反誓约怎么办"（我的建议：**立刻作废该誓约，不惩罚、不提示**，结算时少一档倍率）。

## 5. 待确认清单

1. **数值走 A 还是 B？**（第 3 节）
2. **誓约违反后怎么处理？** 我的建议是"静默作废"，另一种是"当场提示违约、本局道心清零"。
3. **挑战能不能和难度叠加？** 我倾向可以（荒年 + 三誓约），但如果觉得太难筛，可以限定"挑战固定用寻常年景"。
4. **需不需要"挑战记录"**（像成就那样记下"在永夜 + 不点灯下活了 20 日"）？这会多一张表和一个界面，我建议**先不做**。
